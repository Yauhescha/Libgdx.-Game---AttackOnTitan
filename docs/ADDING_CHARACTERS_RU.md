# Как добавить персонажа

Все персонажи описаны в `assets/config/characters.json`. В Java нет списка имён, цен или количества кадров для конкретных персонажей. Игра читает каталог при старте, магазин использует тот же каталог, а покупки сохраняются по `id`.

## Минимальный пример: Levi

1. Создать папку **`assets/player/levi/`**.
2. Положить в неё **`stand.png`** — обязательную статичную картинку персонажа.
3. Добавить следующий объект в конец массива `characters` файла **`assets/config/characters.json`**. Перед новым объектом должна быть запятая после предыдущего.

```json
{
  "id": "LEVI",
  "title": "Levi",
  "assetDir": "levi",
  "price": 250,
  "hookForce": 1200,
  "moveFactor": 1.2,
  "attackRadius": 80
}
```

Копия примера с параметрами скорости анимации лежит в `docs/character-example.json`. Это образец для вставки, он сам не добавляет Levi в игру и не содержит его графику.

Для Android после добавления ассетов и записи пересобрать и установить APK. Каталог читается при запуске; редактирование папок проекта не изменяет уже установленный APK. Java-код менять не требуется.

## Папки и файлы

| Путь внутри `assets/player/levi/` | Назначение |
| --- | --- |
| `stand.png` | Статичный спрайт, обязателен |
| `attack/1.png`, `attack/2.png`, … | Кадры атаки, любое количество |
| `dead/1.png`, `dead/2.png`, … | Кадры смерти, любое количество |
| `attackEffect/1.png`, `attackEffect/2.png`, … | Собственный эффект клинков, необязателен |
| `sound/attack.wav` | Собственный звук атаки, необязателен |
| `sound/dead1.wav`, `sound/dead2.wav`, … | Звуки смерти; случайный выбирается один раз при смерти |

Сканируется только содержимое этих папок, без вложенных подпапок. Для кадров используются PNG, для звуков — WAV, OGG, MP3.

Кадры упорядочиваются по последнему числу в имени: `1`, `2`, …, `10`. Поддержаны и старые имена `attack (0).png`. Файлы без числа идут после нумерованных в алфавитном порядке. Используйте одинаковый размер холста и положение персонажа во всех кадрах, чтобы анимация не дёргалась.

Без папки атаки или смерти соответствующая анимация отображает `stand.png`. Без собственного эффекта клинков используется общий. Без своих звуков используются общие звуки из верхней части конфига. Поэтому можно сначала добавить один спрайт, а затем дорисовать кадры и положить звуки.

При автоматическом поиске звуков все аудиофайлы из `sound/`, кроме используемого звука атаки, считаются звуками смерти. Для других наборов файлов задайте `deathSounds` явно.

## Параметры персонажа

| Поле | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `id` | Обязательно | Уникальный постоянный ID для покупок и выбранного героя |
| `title` | Значение `id` | Имя в магазине |
| `assetDir` | `id` в нижнем регистре | Папка внутри `assets/player/` |
| `price` | `0` | Цена в монетах; 0 — доступен сразу |
| `hookForce` | `1000` | Ускорение при использовании якоря |
| `moveFactor` | `1.0` | Множитель максимальной скорости |
| `attackRadius` | `70` | Радиус атаки в игровых единицах |
| `attackFrameDuration` | `0.1` | Секунд на кадр атаки |
| `deathFrameDuration` | `0.1` | Секунд на кадр смерти |
| `attackEffectFrameDuration` | `0.1` | Секунд на кадр собственного эффекта клинков |
| `stand` | `stand.png` | Путь статичного спрайта относительно папки персонажа |
| `enabled` | `true` | `false` скрывает персонажа и отключает загрузку его ассетов |
| `attackFrames` | Автопоиск в `attack/` | Явный список кадров и их порядок |
| `deathFrames` | Автопоиск в `dead/` | Явный список кадров смерти |
| `attackEffectFrames` | Автопоиск в `attackEffect/` | Явный список кадров эффекта |
| `attackSound` | `sound/attack.wav`, иначе общий | Явный путь звука атаки; пустая строка отключает звук |
| `deathSounds` | Автопоиск в `sound/`, иначе общие | Явный массив звуков смерти; `[]` отключает звук |

Для длительности кадров задавайте число больше нуля. Например, `0.05` — 20 кадров/с, `0.1` — 10 кадров/с. Количество кадров задавать не нужно: оно берётся из папки или явного массива.

Все пути в записи персонажа относительны к `assets/player/<assetDir>/`, используют `/` и учитывают регистр. Порядок записей в массиве `characters` определяет порядок карточек. После пятой карточки магазин автоматически создаёт следующую страницу.

## Если нужны другие названия файлов или порядок

Можно добавить к записи такие поля:

```json
{
  "stand": "portrait.png",
  "attackFrames": ["attack/start.png", "attack/slash.png", "attack/end.png"],
  "attackFrameDuration": 0.08,
  "deathFrames": ["dead/fall.png", "dead/ground.png"],
  "deathFrameDuration": 0.15,
  "attackSound": "sound/slash.ogg",
  "deathSounds": ["sound/voice1.ogg", "sound/voice2.ogg"]
}
```

Это дополнительные поля внутри существующей записи, а не отдельный персонаж. Явный массив полностью заменяет автопоиск соответствующего типа. Отсутствующее поле включает автопоиск. Пустой массив кадров атаки/смерти даёт статичный спрайт, пустой массив кадров эффекта — общий эффект.

## Общие настройки каталога

| Поле в корне конфига | Назначение |
| --- | --- |
| `defaultCharacter` | Стартовый персонаж; доступен сразу независимо от цены |
| `defaultAttackSound` | Общий звук атаки, путь относительно `assets/`; `""` отключает |
| `defaultDeathSounds` | Общие звуки смерти, пути относительно `assets/`; `[]` отключает |
| `defaultAttackEffectFrames` | Кадры общего эффекта клинков, пути относительно `assets/`; нужен непустой массив |
| `defaultAttackEffectFrameDuration` | Секунд на кадр общего эффекта клинков |
| `characters` | Массив всех персонажей |

Общие изображения эффекта продублированы в `assets/effect/attack/`, общие звуки смерти — в `assets/audio/death/`. Это оригинальные файлы из прежнего проекта. Общие ресурсы больше не требуют наличия папки конкретного персонажа. Исходные папки при этом сохранены.

`defaultCharacter` должен ссылаться на включённую запись. Если такой записи нет, стартовым становится первый включённый персонаж. Если ранее выбранного героя удалили или выключили, игра использует стартового; запись о покупке удалённого героя остаётся в сохранениях.

Не меняйте `id` существующего героя при редактировании цены, имени или графики: именно по нему сохраняются покупки. ID должны быть уникальными; хотя бы один персонаж должен оставаться включённым. Имена текущих ID сохранены, поэтому перенос старого прогресса продолжает использовать прежние ключи.

Тесты, сборка, запуск игры и дополнительные проверки в этом изменении не выполнялись по просьбе пользователя.
